# استمرارية العمل إذا توقف الموقع أو الاستضافة

دليل للمالك: ما يحمي المختبرات إن توقفت الاستضافة أو حُذف المشروع، وما يجب أن تفعله أنت مسبقاً، وكيف تعيد الموقع على استضافة أخرى أو تشغّل التطبيق على حاسوب المختبر.

## الفكرة

- **البيانات على حواسيب المختبرات، لا على الموقع.** المحطات تعمل بلا إنترنت بعد أول فتح (`public/local-sw.js`)، وتوقف الموقع لا يمسّ بياناتها.
- **الرمز لا يُقفل إلا بأمرك.** الجهاز لا يُقفل إلا برفض موقّع بمفتاح التوقيع، ولا يقبل ترخيصاً إلا من المفتاح نفسه. موقع آخر على العنوان، أو قاعدة جديدة، لا يقفل المختبرات.
- **ما يبقى بيدك دائماً:** «ضمان الاستمرارية» لكل رمز، و«رمز التجديد بلا إنترنت»، و«نسخة مفتاح التوقيع».
- **ما يبقى بيد المختبر دائماً:** «النسخة الشاملة» والحفظ التلقائي في مجلد، وزر التنزيل في شاشة القفل نفسها.

## ما تفعله الآن (مرة واحدة، ثم دورياً)

| ماذا | أين | لماذا |
|---|---|---|
| **نطاق خاص تملكه** (مثلاً `lab.example.com`) | Vercel ← المشروع ← Settings ← Domains، ثم سجلات DNS عند مزوّد النطاق | بيانات كل مختبر مربوطة بعنوان الموقع في المتصفح. إذا نقلت الاستضافة وبقي العنوان، تبقى البيانات والنسخة المحفوظة كما هي. عنوان `*.vercel.app` يضيع بحذف المشروع. **هذا أهم إجراء.** |
| **نسخة مفتاح التوقيع** | `/license` ← الإعدادات العامة ← «نسخة مفتاح التوقيع» | بدونها لا يمكن تجديد الرموز أو إيقافها من موقع جديد، فتحتاج كل الأجهزة إعادة تفعيل. احفظ الملف وعبارة الحماية في مكانين مختلفين. |
| **نسخة الرموز** | `/license` ← «نسخة احتياطية للرموز» | الرموز والأجهزة والسجل والإعدادات. تُستعاد بالدمج على أي قاعدة. |
| **متغيرات البيئة** | مدير كلمات المرور | `LICENSE_ADMIN_PASSWORD`، `AUTH_SECRET`، `DATABASE_URL` وغيرها (انظر `.env.example`). |
| **نسخة قاعدة البيانات** (إن كان `DATABASE_URL` مضبوطاً) | لوحة مزوّد القاعدة (Neon / Supabase)، أو `pg_dump "$DATABASE_URL" > lab.sql` | للوحة الإدارة المدفوعة وما فيها. |
| **«ضمان الاستمرارية»** | `/license` ← الإعدادات العامة (للرموز الجديدة، وزر «تطبيقه على كل الرموز الحالية»)، أو تفاصيل كل رمز | 0 افتراضياً. مثلاً 30 يوماً: إن تعذّر الوصول إلى الموقع 14 يوماً قبل نهاية الرمز، يبقى يعمل 30 يوماً بعدها. الرموز التجريبية بلا ضمان. |
| **«كلمة مرور النسخ»** (للمختبرات) | «محطة المزامنة ← النسخة الشاملة» | تشفّر كل نسخة شاملة من الجهاز، فلا يقرأ بيانات المراجعين من يجد الملف. إن نُسيت لا تُفتح النسخ المشفّرة بها. |

## إذا توقفت الاستضافة: إعادة الموقع في مكان آخر

1. **الاستضافة البديلة:** أي مكان يشغّل Node.js 20+ أو حاويات:
   - **بحاوية** (Railway، Render، خادم خاص): `Dockerfile` في جذر المشروع جاهز. البيانات في `/data` (اربطه بقرص دائم)، أو اضبط `DATABASE_URL`.
   - **بدون حاوية:** `npm ci && npm run build && npm start`.
2. **متغيرات البيئة:** نفسها كما كانت. `AUTH_SECRET` جديد يعمل أيضاً، لكن يلزمه الخطوة 4.
3. **الرموز:** ادخل `/license` على الموقع الجديد، ثم «استعادة نسخة الرموز».
4. **المفتاح:** «نسخة مفتاح التوقيع» ← اختر الملف واكتب العبارة ← «استعادة». الأجهزة الحالية تستمر بلا إعادة تفعيل.
5. **العنوان:** وجّه نطاقك الخاص إلى الاستضافة الجديدة. إن كان العنوان جديداً فالمختبرات تنقل بياناتها إليه بـ«النسخة الشاملة»: «محطة المزامنة ← النسخة الشاملة ← تنزيل» على العنوان القديم، ثم «استعادة» على الجديد.

## النسخة المحلية: التطبيق على حاسوب المختبر

للطوارئ (الموقع متوقف نهائياً)، أو لمختبر يريد العمل بلا خادم خارجي:

- **Windows:** شغّل `scripts\local\start-lab.cmd` (نقرتان).
- **Linux / macOS:** `./scripts/local/start-lab.sh`.

ما يفعله السكربت:
- يحتاج [Node.js](https://nodejs.org) 20 أو أحدث.
- أول تشغيل يثبّت الحزم ويبني التطبيق (دقائق)، وبعده يبدأ فوراً.
- يفتح `http://localhost:3000/welcome`.
- البيانات في المجلد `lab-data` بجانب المشروع، ويُغيَّر بـ `PGLITE_DATA_DIR`.
- لا يُطلب رمز مختبر ما لم يُضبط `LICENSE_ADMIN_PASSWORD`.
- لخادم الشبكة المحلية (مزامنة حواسيب المختبر بلا إنترنت) اضبط `LAN_HUB_KEY` قبل التشغيل.
- بعد تحديث المشروع على Windows احذف المجلد `.next` ليُبنى من جديد. سكربت Linux / macOS يعيد البناء بنفسه.

**حواسيب المختبر الأخرى** تفتحها بعنوان حاسوب التشغيل على الشبكة (مثلاً `http://192.168.1.10:3000/welcome`). جُرّبت كل المحطات بهذا العنوان ونجحت، مع هذه الحدود، لأن المتصفح لا يعدّ عنوان `http://` على الشبكة آمناً كـ`localhost`:
- لا نسخة محفوظة للعمل بلا اتصال: تحتاج حاسوب التشغيل يعمل. البيانات نفسها تبقى في متصفح كل حاسوب.
- لا «حفظ تلقائي في مجلد»: التنزيل اليدوي للنسخة الشاملة والتذكير يعملان، وكلمة مرور النسخ تعمل أيضاً.
- لوحة الإدارة الكاملة تعمل من كل الحواسيب: السكربت يضبط `LAB_LOCAL_HTTP=1` فتُقبل جلسة الدخول على `http://`. لا تضبطه على موقع يعمل بـ https.

إن أردت كل الميزات على حاسوب آخر، شغّل عليه السكربت نفسه، وزامن بينهما بـ«المزامنة بملف» أو بخادم الشبكة المحلية.

**نقل بيانات المختبر إليها:** البيانات في المتصفح مربوطة بالعنوان، فـ`localhost` يبدأ فارغاً:
1. على العنوان القديم: «محطة المزامنة ← النسخة الشاملة ← تنزيل».
   - والمحطات مقفلة: زر «تنزيل نسخة شاملة» في شاشة القفل.
   - بلا وصول إلى العنوان القديم: آخر ملف في مجلد الحفظ التلقائي.
2. في النسخة المحلية: «محطة المزامنة ← النسخة الشاملة ← استعادة».

## ما يعمل بدون الموقع

يظهر للمختبر أيضاً في «عن التطبيق ← حالة الخدمة» (`/about/status`) مع فحص مباشر لهذا الجهاز.

| الميزة | بدون الموقع | البديل |
|---|---|---|
| المحطات كلها | تعمل | — |
| رمز المختبر | يعمل حتى نهايته | «ضمان الاستمرارية»، «رمز التجديد بلا إنترنت» |
| النسخ الاحتياطية والنسخة الشاملة | تعمل | — |
| المزامنة التلقائية عبر الإنترنت | تتوقف | «المزامنة بملف»، أو خادم الشبكة المحلية (`LAN_HUB_KEY`) |
| محطة التواصل: المحادثة العامة والصندوق المشفّر | يتوقفان | المحادثة بين حواسيب المختبر بملف أو على الشبكة المحلية |
| نافذة الأطباء | تتوقف | النسخة المحلية على شبكة المختبر |
| تفعيل جهاز جديد | يتوقف | النسخة الشاملة إلى النسخة المحلية |
| لوحة الإدارة الكاملة | تتوقف | — |

## الاختبارات

- `codes.continuity.cjs`: موقع بلا المفتاح لا يقفل، ضمان الاستمرارية، رمز التجديد، نسخة المفتاح، والتنزيل من شاشة القفل.
- `sync.backup.cjs`: النسخة الشاملة، الاستعادة، التذكير، والحفظ التلقائي في مجلد.
- `about.status.cjs`: صفحة «حالة الخدمة».
- `offline.routes.cjs` و`station.outage.cjs`: كل صفحة محفوظة للعمل بلا إنترنت، وكل محطة تفتح والخادم متوقف.
