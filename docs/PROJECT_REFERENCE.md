# مرجع مشروع Spir Lab Manager — دليل المعمارية والقرارات

> وثيقة مرجعية شاملة تجمع: الخطة، ملخص نقاش الاختيار، تحليل المشاريع الثمانية،
> تحليل مشروع `Spir-Margin`، القرار المعماري، ومخطط قاعدة البيانات وخريطة الطريق.
> آخر تحديث: 2026-09-16.

---

## 1. الهدف

بناء **تطبيق احترافي لإدارة مختبرات التحاليل الطبية** (Laboratory Analysis
Management)، موجّه بالكامل لإدارة المختبرات فقط، حسب مواصفات ملف
`Laboratory_App_Specification.pdf`.

- **الاستضافة:** Vercel (Serverless).
- **قاعدة البيانات:** Postgres — قابلة للتشغيل محلياً على PGlite (WASM مدمج، صفر
  إعداد)، وقابلة للربط بـ Supabase المستضاف عبر `DATABASE_URL`.
- **الفلسفة:** توأمة تقنية مع البرنامج المحاسبي `Spir-Margin` لإتاحة **قاعدة
  بيانات مشتركة** لاحقاً وهوية بصرية موحّدة، مع إبقاء تطبيق المختبر مستقلاً في
  النشر والتركيز.

---

## 2. ملخص نقاش الاختيار (كيف وصلنا لهذا القرار)

1. المستخدم رفع مواصفات PDF لتطبيق إدارة مختبر تحاليل، وحدّد استخدام **Vercel +
   قاعدة بيانات**، وطلب اقتراح **أفضل حل** (مرحلة نقاش أولاً).
2. قدّم قائمة بـ **8 مشاريع GitHub** + أشار لبرنامجه المحاسبي `Spir-Margin`.
3. عند الفحص تبيّن أن `Spir-Margin` مبني على **Next.js 14 + Supabase + TypeScript**
   ويحوي أصلاً نصف المواصفات (مخزون كواشف، خصم تلقائي، مصروفات، أوامر شراء، RLS).
4. **القرار المختار من المستخدم:** «تطبيق منفصل + قاعدة بيانات مشتركة» — تطبيق
   مختبر جديد نظيف بنفس مكدس `Spir-Margin`، يُنشر مستقلاً، ويشارك قاعدة Supabase.
5. توجيه إضافي: **التركيز الكامل على إدارة المختبرات فقط**، والاستلهام من مشاريع
   المختبرات (خاصة DiagLab/AURA) في الواجهة وتجربة الاستخدام.

## 4. تحليل مشروع Spir-Margin (الأساس التقني)

- **المستودع:** https://github.com/inzohussein-blip/Spir-Margin
- **المكدس:** Next.js 14 (App Router) · TypeScript · Tailwind CSS v4 · Radix UI ·
  React Hook Form · TanStack Table · `sonner` · `lucide-react`.
- **البيانات:** طبقة `src/lib/db` بواجهة موحّدة `query(sql, params)` — خلفيتان
  متبادلتان: PGlite (WASM مدمج، افتراضي) و node-postgres (عند ضبط `DATABASE_URL`).
- **المصادقة:** جلسات موقّعة بـ `jose` (`src/lib/auth`).
- **الهجرات:** 82 هجرة SQL تحت `supabase/migrations`.
- **مطابقة ERPNext → جداول:** Company/Supplier → `companies` · Location → `labs`
  · Warehouse → `warehouses` · Item → `products` · Batch → `kit_batches` ·
  Stock Ledger → `stock_movements` · Sales Invoice → `sales`.

### ما يغطّيه Spir-Margin أصلاً من مواصفات المختبر

| قسم المواصفات | التغطية في Spir-Margin |
|---|---|
| **3. إدارة المخزون** (كواشف/كِتات، خصم تلقائي، تنبيه حد أدنى، صلاحية) | ~90% — `products`, `kit_batches`, `stock_movements`, هجرة `0076_sale_stock_deduction` |
| **4. الطلبيات والمصروفات** (مورّد، تقارير مالية) | ~90% — أوامر شراء + مصروفات + `journal_entries` |
| **2. السجل المالي واليومي** | جزئياً — `sales` + views مالية |
| **8. لوحة تحليلات + نسخ احتياطي سحابي** | جزئياً — Supabase يوفّر النسخ الاحتياطي |

> **قرار التوحيد:** تطبيق المختبر يستخدم نفس مشروع Supabase، ويشارك `AUTH_SECRET`
> لتسجيل دخول موحّد (SSO). جداول المختبر الجديدة تُعزل ببادئة/نطاق لتفادي التصادم.

## 5. القرار المعماري النهائي

**تطبيق مختبر مستقل + قاعدة بيانات مشتركة**، بنفس مكدس `Spir-Margin`.

```
┌─────────────────────┐        ┌─────────────────────┐
│  spir-lab-manager   │        │     Spir-Margin     │
│  (تطبيق المختبر)     │        │   (المحاسبة/ERP)    │
│  Next.js @ Vercel   │        │  Next.js @ Vercel   │
└──────────┬──────────┘        └──────────┬──────────┘
           │        نفس AUTH_SECRET (SSO)   │
           └───────────────┬───────────────┘
                           ▼
              ┌────────────────────────┐
              │   Supabase Postgres    │
              │  مخزون/كواشف/ماليات    │ ◄── مشترك
              │  + جداول المختبر الجديدة│
              └────────────────────────┘
```

- تشغيل محلي بلا إعداد عبر PGlite؛ إنتاج عبر `DATABASE_URL` (Supabase).
- تفعيل RLS على كل جداول بيانات المرضى (بيانات حسّاسة).

## 7. المكدس التقني المختار

- **الإطار:** Next.js 14 (App Router) + TypeScript (strict).
- **الواجهة:** Tailwind CSS v4 + Radix UI + `lucide-react` + `sonner`؛ RTL عربي أساسي.
- **البيانات:** `src/lib/db` بواجهة `query()` — PGlite محلياً / `pg` مع `DATABASE_URL` إنتاجاً.
- **المصادقة:** `jose` (جلسات موقّعة) — مشاركة `AUTH_SECRET` مع Spir-Margin.
- **التقارير:** `@react-pdf/renderer` (A4) + `qrcode`؛ تصدير صورة PNG/JPG للواتساب.
- **الذكاء:** `@anthropic-ai/sdk` — نموذج `claude-sonnet-5`.

---

## 8. خريطة الطريق (مراحل البناء)

- **م0 — السقالة (منجزة):** إعداد المشروع، طبقة البيانات، مخطط قاعدة البيانات
  الكامل، بيانات تجريبية، هيكل الواجهة RTL، صفحة تسجيل الدخول، لوحة التحكم.
- **م1 — المرضى والنتائج:** إضافة مريض، بحث سريع، إدخال نتائج مع ترميز H/L،
  الفحوصات الخاصة (بول/براز: فحص عيني ومجهري).
- **م2 — التقارير:** توليد PDF بمقاس A4 + QR، تصدير صورة.
- **م3 — التقويم واليومي:** عرض تقويمي + ملخص إحصائي يومي (عدد المراجعين/الدخل).
- **م4 — المخزون:** ربط الفحص باستهلاك الكاشف، تنبيهات الحد الأدنى والصلاحية.
- **م5 — الطلبيات والمصروفات + الكادر والبدلاء.**
- **م6 — واتساب + المساعد الذكي.**

## 9. قرارات عالقة (تُحسم عند الحاجة)

1. **قاعدة Supabase المشتركة:** هل توجد بيانات مشروع Supabase مستضاف حالي لـ
   `Spir-Margin` (نضبط `DATABASE_URL` و`AUTH_SECRET` نفسيهما)، أم ننشئ مشروع
   Supabase مشتركاً جديداً؟ (حتى ذلك الحين: التطوير يعمل على PGlite بلا إعداد.)
2. **واتساب:** بدء بـ `wa.me` (MVP، بلا توثيق) ثم الترقية لـ WhatsApp Cloud API
   الرسمي (إرسال حقيقي مع مرفق PDF، يتطلب توثيق حساب أعمال).
