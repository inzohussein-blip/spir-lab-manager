# Spir Lab Manager — إدارة مختبرات التحليلات المرضية

منصة عربية (RTL) لتأجير برنامج إدارة المختبرات: خمس محطات مجانية تعمل على الجهاز نفسه
بلا إنترنت، ولوحة إدارة كاملة مدفوعة لكل مختبر بقاعدة بياناته، ومدير رموز للمالك يفعّل
المختبرات ويتابعها.

- **الإطار:** Next.js 16 (App Router) + React 19 + TypeScript
- **الواجهة:** Tailwind CSS v4 — عربي RTL، فاتح/داكن، أرقام لاتينية
- **البيانات:** المحطات في المتصفح (IndexedDB)؛ لوحة الإدارة والرموز على Postgres
  (PGlite مدمج محلياً، أو Postgres مستضاف مثل Neon / Supabase / Railway)
- **الاستضافة:** Vercel

> خطة المشروع الأصلية ومواصفاته في [`docs/PROJECT_REFERENCE.md`](docs/PROJECT_REFERENCE.md)
> و[`docs/Laboratory_App_Specification.pdf`](docs/Laboratory_App_Specification.pdf).

## أجزاء المنصة

### 1. المحطات المحلية (مجانية، تعمل بلا إنترنت)

تُفتح من صفحة الترحيب `/welcome`. كل محطة مستقلة تماماً، وبياناتها على الجهاز نفسه،
وتعمل بلا إنترنت بعد أول فتح (نسخة محفوظة عبر `public/local-sw.js`).

| المحطة | المسار | أبرز ما فيها |
|---|---|---|
| محطة المختبر | `/station` | إدخال النتائج مع «تمييز» نتيجة بلون على التقرير (وحقول الاستمارات أيضاً) وزر طباعة أسفل النتائج، الاستمارات (إدرار، خروج، سائل منوي، زرع)، تقرير A4/A5، باركود وملصقات أنابيب، سلة محذوفات، نسخ احتياطي |
| المخزن والمشتريات | `/store` | «المشتريات»، و«المخزن» (الموجود الآن ونتائج بانتظار الصرف)، و«الأصناف» (تحاليل «إدارة الفحوصات» وموادها والأنابيب)، والموردون وتقارير الشراء |
| محطة التدريب والمعلومات | `/training` | مكتبة الفحوصات، البروسيجر المطبوع، وضع العرض، الاختبارات والشهادات |
| محطة الجودة والأجهزة | `/qc` | السيطرة النوعية والأجهزة |
| محطة الكادر والدوام | `/roster` | الكادر والمناوبات والدوام |
| محطة المزامنة | `/sync` | مزامنة بيانات المحطات بين حواسيب المختبر: بملف، أو تلقائياً عبر مكان المختبر على الخادم |

**أسفل صفحة الترحيب:** اختيار المظهر (تلقائي / فاتح / غامق، وتتبعه كل محطة مضبوطة على «تلقائي»)، ونبذة عن SPIR (شركة برمجة)،
وسياسة الخصوصية وإخلاء المسؤولية («نحن لا نتحمل أي مسؤولية»).

**التواريخ** في كل المحطات بأرقام إنكليزية والأشهر أرقام (2026-09-30).

**الإعدادات** في كل محطة ولوحة الإدارة بنفس الشكل:
- أقسام بقائمة جانبية (شريط أفقي على الهاتف)، والقسم المفتوح يُحفظ في العنوان (`#report` مثلاً).
- بحث يجد أي خيار، وشارة بعدد المفعّل في كل قسم.
- حفظ فوري مع علامة «حُفظ ✓».
- ترتيب واحد: أقسام المحطة الخاصة، ثم «الجهاز والبيانات» (النسخ الاحتياطي والمزامنة)، ثم «الأمان والمظهر» (رمز الدخول والألوان).
- محطة المختبر: «المختبر» (الاسم والشعار ومعلومات التواصل)، «التقرير المطبوع» (الألوان والجدول، ما يظهر على الورقة، رمز QR، التوقيع، الورق والخط)،
  «الاستمارات»، «شاشة الإدخال»، «المخزن»، «الفحوصات والأطباء»، «الجهاز والبيانات»، «الأمان والمظهر».
- في المخزن والمشتريات والكادر والجودة: ترويسة للمطبوعات بشعار خاص، وزر «نسخ من محطة المختبر».
- **رمز الدخول (PIN):** لا رمز في البداية؛ يُفعَّل لكل محطة من «الأمان والمظهر»، ويُطلب مرة لكل نافذة.
  إذا نُسي يعيّنه المالك أو يزيله من `/licenses`، ويأخذه الجهاز بـ«نسيت الرمز؟ ← تحديث من المزوّد».

**ربط المحطات** (كلها عدا التدريب، على الحاسوب نفسه):
- المخزن في «المخزن والمشتريات»: يُحسم منه عند إدخال فحص مرتبط (محطة المختبر) وعند كل إدخال سيطرة لمادة كنترول مرتبطة (الجودة)، ويُضاف إليه ما يُشترى.
- الجودة: أسماء الفحوصات من محطة المختبر، و«المنفّذ» من الكادر، وشركة صيانة الجهاز من موردي المشتريات (مع هاتفه).

**محطة المزامنة** (`/sync`): «ملف المزامنة» يُصدَّر من حاسوب ويُدخل في آخر (يُضاف الناقص، ويؤخذ الأحدث، ويُحذف ما حُذف لاحقاً)،
أو «المزامنة التلقائية» كل 30 ثانية عبر مكان المختبر على الخادم (`/api/company-sync`، بالترخيص الموقّع للجهاز فقط)،
أو عبر «خادم الشبكة المحلية» (`LAN_HUB_KEY`) على حاسوب المختبر بلا إنترنت. من إعداداتها تُختار المحطات المشتركة.

**المخزن والمشتريات:** بيانات المخزن مشتركة مع محطة المختبر والجودة على الجهاز نفسه:
- الإدخال بسيط: كل إضافة أو تعديل في نافذة صغيرة (اسم وكمية ثم «حفظ»)، والقوائم نظيفة مع بحث وتصفية بنقرة.
- «المشتريات» (`/store`): زر «عملية شراء جديدة» (التاريخ، المورّد، البنود — Enter في خانة السعر يضيف بنداً — ثم «مدفوعة»)؛
  القائمة الأحدث أولاً مع تصفية «الكل / غير مدفوعة / مدفوعة»، وزر «تم الدفع» يحوّل غير المدفوعة إلى مدفوعة
  (والنقر على «مدفوعة» يرجعها)، والنقر على العملية يعرض بنودها.
- «المخزن» (`/store/inventory`): كل صنف بكميته بخط كبير و«نفد / ناقص»، وتصفية «نفد أو ناقص» و«قرب الانتهاء»،
  و«إضافة» و«صرف» في نافذة الكمية (1 افتراضياً، Enter للحفظ)، وزر سجل حركته وتعديله.
- «الأصناف» (`/store/items`) بثلاث علامات تبويب:
  - «الأصناف»: جدول (الصنف، النوع، يُستعمل في، الكمية) و«صنف جديد» (الاسم، كاشف أو أنبوب، الكمية، التنبيه، الانتهاء،
    والتحاليل التي تستعمله)، وزر «الأنابيب والمستلزمات الشائعة»؛
  - «التحاليل وموادها»: كل تحليل من «إدارة الفحوصات» في محطة المختبر ومادته (زر «مادة» يضيف «كاشف …» مرتبطاً به،
    أو مادة لكل تحليل بلا مادة دفعة واحدة)؛
  - «الكتات»: الكت علبة تُشترى وتحتوي أصنافاً بكميات (مثلاً 4 × كاشف + 1 × محلول معايرة)؛
    يُكتب اسم الكت في «المشتريات» فتُضاف محتوياته × عدد الكتات إلى المخزن.
- «الجرد» (`/store/count`): الكمية المعدودة على الرف مقابل المسجَّلة، والفرق، و«حفظ الجرد» يصحّح المعدود فقط؛ تُحفظ عمليات الجرد
  وتُطبع ورقة الجرد للعدّ بالقلم.
- «سجل الحركة» (`/store/moves`): كل تغيّر في الكمية (شراء، حذف شراء، نتائج، سيطرة، إضافة/صرف يدوي، جرد، تعديل) مع الكمية بعده
  (`station.stockMoves.v1`، آخر 3000 حركة).
- خيارات إضافية موقوفة في البداية (إعدادات المخزن والمشتريات ← خيارات إضافية):
  - **ديون الموردين:** «المدفوع الآن» ودفعات لاحقة لكل عملية («تم الدفع» يسجّل المتبقي دفعة)، والمتبقي لكل مورّد، وكشف حساب المورّد للطباعة؛
  - **الأسعار وقيمة المخزن:** سعر الوحدة من آخر شراء (أو يُكتب)، وقيمة المخزن، وكلفة المواد لكل فحص؛
  - **الباركود:** لكل صنف وكت، ومسحه بقارئ الباركود في المشتريات والمخزن والجرد.
- حسم المواد (خيار واحد في إعدادات محطة المختبر وإعدادات المخزن والمشتريات ← المخزن): **تلقائي** عند حفظ النتيجة
  وعند كل إدخال سيطرة، أو **يدوي** — زر «صرف المواد من المخزن» تحت النتائج في شاشة الإدخال، أو «المخزن ← بانتظار الصرف»
  (الزيارات وإدخالات السيطرة) مع «صرف» و«تجاهل». لا تُحسم مواد الزيارة أو إدخال السيطرة مرتين أبداً
  (السجلان `station.stockUsed.v1` و`station.stockUsedQc.v1`).
- تُحسم وحدة من الصنف تلقائياً عند إدخال فحص مرتبط به في محطة المختبر؛
- كل بند مشترى يُضاف إلى المخزن (الموجود تُزاد كميته والجديد يُضاف صنفاً)، وحذف عملية الشراء يطرح الكميات.
- كل صنف يُربط بفحوصات محطة المختبر: الكاشف يُحسم وحدةً لكل فحص، والأنبوب أو العلبة أو السرنجة وحدةً لكل زيارة؛
  وزر «الأنابيب والمستلزمات الشائعة» يضيفها مرتبطة بفحوصاتها (EDTA لأمراض الدم، الجل للكيمياء، علب الإدرار والخروج…).
- «عند نفاد المادة» (خيار واحد يظهر في إعدادات محطة المختبر وإعدادات المخزن والمشتريات، موقوف في البداية):
  تحذير «غير متوفر في المخزن» تحت الفحص وتنبيه عند الحفظ (تُحفظ النتيجة)، والسماح بالرصيد السالب (مثلاً -1) بدل التوقف عند 0.
- حقول الأرقام تقبل الكتابة بلوحة المفاتيح العربية وتحوّلها إلى 1 2 3، والمبالغ تظهر بالشكل 25,000.

**فحص الإدرار العام (G.U.E):** الخلايا (القيح وكريات الدم الحمراء) والفحوص الكيميائية (الألبومين، السكر، الكيتون، الصفراء)
بالإشارات Nil, +, ++, +++, ++++, More than (++++) — بدون أرقام وبدون Trace.

**التقرير المطبوع في محطة المختبر** (الإعدادات):
- باركود رقم العينة بجانب معلومات المريض يمكن إخفاؤه (يبقى الرقم مطبوعاً).
- الفحوص ذات النتيجة الموجبة/السالبة تُطبع بلا مدى مرجعي ولا Flag.
- «تمييز» في استمارات الإدرار والخروج والسائل المنوي والزرع: لكل حقل (وسطر الزرع وكل مضاد) علامة تلوّنه على التقرير.
- «ملء الصفحة عند قلة الفحوصات» (موقوف في البداية): يكبر خط الجدول وتتسع أسطره كلما قلّت الفحوص.
- زر «واتساب» بجانب زر الطباعة: التقرير ملف PDF يُشارك، أو يُحفظ ويُفتح واتساب على رقم المريض.
- ألوان المختبر: ألوان جاهزة أو خاصة، وشدة الألوان، مع معاينة فورية.
- شكل جدول النتائج (الخط، الأسطر، الكثافة…).
- خيارات إضافية موقوفة في البداية:
  - الطباعة على ورق مطبوع مسبقاً؛
  - مكان الشعار والعلامة المائية؛
  - خط التقرير (Cairo / Tajawal / Noto Naskh / Amiri، مضمّنة للعمل بلا إنترنت).
- التوقيع والختم، ورمز QR بمعلومات المختبر.

### 2. لوحة الإدارة الكاملة (مدفوعة) — `/`

- المرضى والطلبات والنتائج والفواتير والمخزون والمشتريات والكادر والمواعيد والجودة.
- واتساب ومساعد ذكي اختياري.
- يدخلها المختبر بحساب مستخدم (`/login`).
- لكل مختبر هويته في الإعدادات:
  - اسمه وشعاره؛
  - ألوان تقريره؛
  - التوقيع والختم؛
  - التقرير بالعربية أو الإنجليزية، مع زر للتبديل عند كل طباعة.
- **بيانات كل مختبر منفصلة:**
  - إما في قاعدة بيانات خاصة به (يربطها المالك أو المختبر نفسه)؛
  - أو في قسم مستقل له داخل قاعدة الموقع (مخطط `lab_<id>`).
  - يمكن إلزام الرموز المدفوعة بقاعدة خاصة.
- التحقق من صحة التقرير عبر رمز QR يفتح `/verify/<token>`.

### 3. مدير الرموز (للمالك) — `/licenses`

- **رموز المختبرات:** رمز لكل مختبر يحدد المحطات المفعّلة ومدة الاشتراك، ويرتبط بجهاز
  واحد أو بعدة أجهزة.
- **متابعة الرموز:** سجل الأحداث، والدفعات، ورسائل للمحطات، ورمز دخول المحطات (PIN)، ونسخة احتياطية للرموز.
- **دخول المالك:** بكلمة مرور، مع تحقق بخطوتين اختياري (تطبيق المصادقة).
- **قسم «قواعد البيانات»:** ربط قاعدة كل مختبر بواجهة لكل مزوّد (Neon / Supabase /
  Railway / PostgreSQL آخر) مع تعليماته، وفحص الاتصال، وإعادة كلمة مرور المدير.
- **قسم «الإعدادات العامة»:**
  - مدة الرمز الافتراضية، والمحطات الافتراضية، ومدة التجربة.
  - ميزات موقوفة في البداية: عدة أجهزة للرمز، التسجيل الذاتي (`/signup`)، سجل الأخطاء.
  - ميزة سرية: تصدير بيانات مختبر إلى Excel.

## التشغيل محلياً (بلا إعداد)

```bash
npm install
npm run dev
```

- يعمل التطبيق على PGlite (Postgres مدمج)، ويطبّق الهجرات والبيانات التجريبية تلقائياً.
- دخول لوحة الإدارة التجريبية: `admin` / `admin123`.
- منظومة الرموز موقوفة ما لم يُضبط `LICENSE_ADMIN_PASSWORD`، فتفتح المحطات بلا رمز.

## متغيرات البيئة

انظر [`.env.example`](.env.example) للتفاصيل. أهمها:

| المتغير | الغرض |
|---|---|
| `DATABASE_URL` | Postgres المستضاف للموقع. بدونه: PGlite (مؤقت على Vercel). |
| `AUTH_SECRET` | سر توقيع الجلسات وتشفير روابط قواعد المختبرات ومفتاح الرموز. **إلزامي في الإنتاج.** |
| `LICENSE_ADMIN_PASSWORD` | كلمة مرور المالك لـ `/licenses`، ووجوده يشغّل منظومة الرموز. |
| `LICENSE_URL` | قاعدة مستقلة للرموز (مستحسن). بدونه تُستخدم `DATABASE_URL`. |
| `LICENSE_2FA_OFF` | `1` لإيقاف التحقق بخطوتين مؤقتاً عند فقدان الهاتف. |
| `STATION_ACTIVATION_CONTACT` | سطر التواصل على شاشة التفعيل (يُعدَّل أيضاً من `/licenses`). |
| `NEXT_PUBLIC_BASE_URL` | عنوان الموقع لروابط QR (يُستنتج تلقائياً إن لم يُضبط). |
| `NEXT_PUBLIC_STATION_SYNC` | `1` لإظهار مزامنة المحطات مع قاعدة المختبر (موقوفة افتراضياً). |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | المساعد الذكي في لوحة الإدارة (اختياري). |
| `WHATSAPP_CLOUD_TOKEN` / `WHATSAPP_PHONE_ID` | واتساب Cloud API الرسمي (اختياري؛ بدونه روابط wa.me). |
| `LAB_POOL_IDLE_MIN` / `LAB_POOLS_MAX` | إغلاق اتصالات قواعد المختبرات الخاملة وحدّها الأقصى. |
| `PGSSL` / `PGPOOL_MAX` / `PGLITE_DATA_DIR` | ضبط الاتصال بـ Postgres ومكان بيانات PGlite. |

> لا تُكتب قيم الأسرار في المستودع أو في المحادثات؛ تُضبط في إعدادات Vercel فقط.

## النشر على Vercel

1. أنشئ قاعدة Postgres للموقع (Neon عبر Vercel → Storage، أو Supabase) واضبط `DATABASE_URL`.
2. (مستحسن) قاعدة مستقلة للرموز: Vercel → Storage → Neon باسم `LICENSE` ← `LICENSE_URL`.
3. اضبط `AUTH_SECRET` (`openssl rand -base64 48`) و`LICENSE_ADMIN_PASSWORD`.
4. الإنتاج يُبنى من فرع `main`؛ كل تغيير يمر بطلب دمج تُشغَّل عليه الاختبارات.

الهجرات تحت `supabase/migrations` تُطبَّق تلقائياً على قاعدة الموقع وعلى قاعدة كل مختبر
(جداول لوحة الإدارة فقط؛ جداول الرموز تبقى في قاعدة الرموز).

## الفحوصات والاختبارات

```bash
npx tsc --noEmit     # الأنواع
npm run lint         # ESLint (الأخطاء تُفشل الفحص، والتحذيرات تُعرض فقط)
npm run build
```

اختبارات المتصفح (Playwright) تعمل على خادم مشغَّل:

```bash
# الرموز موقوفة: المحطات والاستمارات والصفحات ولوحة الإدارة
PORT=3456 npm start &
E2E_BASE=http://localhost:3456 npm run test:e2e

# الرموز مفعّلة: مدير الرموز وقواعد المختبرات (يحتاج Postgres في E2E_PG_URL)
PORT=3457 LICENSE_ADMIN_PASSWORD=… AUTH_SECRET=… LAB_DB_ALLOW_PRIVATE=1 npm start &
E2E_BASE=http://localhost:3457 E2E_PG_URL=postgresql://… npm run test:e2e:codes
```

- GitHub Actions (`.github/workflows/tests.yml`) تشغّل كل ذلك على كل دفع وطلب دمج، مع خدمة
  Postgres 16.
- ويعمل تدقيق أمني للحزم (`security.yml`) أسبوعياً وعند كل تغيير في الحزم.
