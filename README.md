# Spir Lab Manager — إدارة مختبرات التحليلات المرضية

منصة عربية (RTL) لتأجير برنامج إدارة المختبرات: محطات مجانية تعمل على الجهاز نفسه
بلا إنترنت، ولوحة إدارة كاملة مدفوعة لكل مختبر بقاعدة بياناته، ومدير رموز للمالك يفعّل
المختبرات ويتابعها.

- **الإطار:** Next.js 16 (App Router) + React 19 + TypeScript
- **الواجهة:** Tailwind CSS v4 — عربي RTL، فاتح/داكن، أرقام لاتينية
- **البيانات:** المحطات في المتصفح (IndexedDB)؛ لوحة الإدارة والرموز على Postgres
  (PGlite مدمج محلياً، أو Postgres مستضاف مثل Neon / Supabase / Railway)
- **الاستضافة:** Vercel

> خطة المشروع الأصلية ومواصفاته في [`docs/PROJECT_REFERENCE.md`](docs/PROJECT_REFERENCE.md)
> و[`docs/Laboratory_App_Specification.pdf`](docs/Laboratory_App_Specification.pdf).

## أجزاء المنصة

### 1. المحطات المحلية (مجانية، تعمل بلا إنترنت)

تُفتح من صفحة الترحيب `/welcome`. كل محطة مستقلة تماماً، وبياناتها على الجهاز نفسه،
وتعمل بلا إنترنت بعد أول فتح (نسخة محفوظة عبر `public/local-sw.js`).

| المحطة | المسار | أبرز ما فيها |
|---|---|---|
| محطة المختبر | `/station` | إدخال النتائج مع «تمييز» نتيجة بلون على التقرير (وحقول الاستمارات أيضاً) وزر طباعة أسفل النتائج، الاستمارات (إدرار، خروج، سائل منوي، زرع)، تقرير A4/A5، باركود وملصقات أنابيب، سلة محذوفات، نسخ احتياطي |
| المخزن والمشتريات | `/store` | «المشتريات»، و«المخزن» (الموجود الآن ونتائج بانتظار الصرف)، و«الأصناف» (تحاليل «إدارة الفحوصات» وموادها والأنابيب)، والموردون وتقارير الشراء |
| محطة التدريب والمعلومات | `/training` | الدليل من الصفر، مكتبة الفحوصات (كل فحوصات محطة المختبر مشروحة)، البروسيجر المطبوع، وضع العرض، الاختبارات والشهادات |
| محطة الجودة والأجهزة | `/qc` | السيطرة النوعية والأجهزة |
| محطة الكادر والدوام | `/roster` | الكادر والمناوبات والدوام |
| محطة التواصل | `/connect` | محادثة داخلية بين حواسيب المختبر، ورسائل مشفّرة لمختبر آخر (اتصال مباشر أو ملف أو صندوق بريد مشفّر)، و«المحادثة العامة» بين كل المختبرات |
| محطة المزامنة | `/sync` | مزامنة بيانات المحطات بين حواسيب المختبر: بملف، أو تلقائياً عبر مكان المختبر على الخادم، مع زر «إيقاف المزامنة» للحماية — وفيها «رموز الأطباء» |
| نافذة الأطباء | `/doctor` | مستقلة مثل `/license` (لا رابط إليها من أي صفحة)، وتُفتح حصراً برمز تفعيل حساب الطبيب من «محطة المزامنة ← رموز الأطباء»، على جهاز الطبيب بلا رمز مختبر: نتائج المراجعين الذين أرسلهم للمختبر، برمز يعطيه إياه المختبر، للمدة التي يختارها المختبر |
| عن التطبيق | `/about` | شرح التطبيق وكل محطة وميزاتها بصور مبسّطة، البدء السريع، النصائح، الأسئلة الشائعة، البيانات والدعم — مفتوحة للجميع بلا رمز |

**مظهر موحّد لكل المحطات:** قائمة جانبية واحدة الشكل (`AppSidebar`: أقسام، ووصف تحت كل صفحة، وأيقونة في مربع، وأرقام تنبيه)
في المختبر والمخزن والتدريب والجودة والكادر والتواصل والمزامنة و«عن التطبيق» ومدير الرموز؛ ولكل محطة لونها (المختبر أخضر مزرق، المخزن كهرماني،
التدريب نيلي، الجودة وردي، الكادر أزرق، التواصل أخضر زمردي، نافذة الأطباء سماوي، المزامنة بنفسجي، «عن التطبيق» أرجواني)، وعنوان كل صفحة بأيقونتها في مربع بلون المحطة
(`globals.css`). المظهر فقط — لم يتغير شيء في عمل الصفحات.

**التنقل:** صفحة الترحيب هي المدخل الوحيد للمحطات. لا تحوي أي محطة أو صفحة (ومنها «عن التطبيق» ومدير الرموز) رابطاً إلى محطة أخرى، بل ترجع كلها إلى صفحة الترحيب. و«نافذة الأطباء» لا ترتبط بأي صفحة أخرى، فلا رابط فيها حتى إلى الترحيب. يتحقق `pages.crawl.cjs` من ذلك في كل الصفحات. هذا في التنقل فقط، أما ربط البيانات بين المحطات فباقٍ كما هو.

**أسفل صفحة الترحيب:** اختيار المظهر (فاتح — الافتراضي — أو غامق أو تلقائي حسب الجهاز) لصفحة الترحيب ومدير الرموز ولوحة الإدارة. لكل محطة (ومنها نافذة الأطباء و«عن التطبيق») مظهرها من إعداداتها، والفاتح هو الافتراضي في كل النوافذ، ونبذة عن SPIR (شركة برمجة)،
وسياسة الخصوصية وإخلاء المسؤولية («نحن لا نتحمل أي مسؤولية»).

**التواريخ** في كل المحطات بأرقام إنكليزية والأشهر أرقام (2026-09-30).

**الإعدادات** في كل محطة ولوحة الإدارة بنفس الشكل:
- أقسام بقائمة جانبية (شريط أفقي على الهاتف)، والقسم المفتوح يُحفظ في العنوان (`#report` مثلاً).
- بحث يجد أي خيار، وشارة بعدد المفعّل في كل قسم.
- حفظ فوري مع علامة «حُفظ ✓».
- ترتيب واحد: أقسام المحطة الخاصة، ثم «الجهاز والبيانات» (النسخ الاحتياطي والمزامنة)، ثم «الأمان والمظهر» (رمز الدخول والألوان).
- محطة المختبر: «المختبر» (الاسم والشعار ومعلومات التواصل)، «التقرير المطبوع» (الألوان والجدول، ما يظهر على الورقة، «التاريخ والوقت»: إظهاره وصيغته 2026-10-03 / 03/10/2026 / 3 تشرين الأول 2026 / 3 Oct 2026، والوقت بلا / 24 / 12 ساعة، ووقت التسجيل أو الطباعة، ومكانه أعلى التقرير أو ضمن معلومات المريض، وعنوانه — والأصلي كما كان، رمز QR، التوقيع، الورق والخط)،
  «الاستمارات»، «شاشة الإدخال»، «المخزن»، «الفحوصات والأطباء»، «الجهاز والبيانات»، «الأمان والمظهر».
- في المخزن والمشتريات والكادر والجودة: ترويسة للمطبوعات بشعار خاص، وزر «نسخ من محطة المختبر».
- **رمز الدخول (PIN):** لا رمز في البداية؛ يُفعَّل في كل المحطات بلا استثناء (ومنها التواصل والمزامنة و«عن التطبيق») من إعداداتها،
  ولكل محطة رمزها المنفصل، ويُطلب مرة لكل نافذة. إذا نُسي يعيّنه المالك أو يزيله من «رموز الدخول (PIN)» في `/license`،
  ويأخذه الجهاز بـ«نسيت الرمز؟ ← تحديث من المزوّد».

**محطة التواصل** (`/connect`، تُفعَّل في رمز المختبر مثل باقي المحطات؛ `src/lib/connect`):
- **المحادثة الداخلية** بين حواسيب المختبر: «رمز المحادثة» نفسه على كل حاسوب (8 أحرف أو أكثر، **غير رمز المزامنة** — يُرفض
  إن طابقه). لا يُحفظ الرمز ولا يصل إلى الخادم: يُشتق منه مفتاح واسم غرفة (PBKDF2)، والخادم يحفظ رسائل مشفّرة فقط
  (XChaCha20-Poly1305)، ولكل مختبر غرفه المنفصلة. تعمل على تثبيت المختبر الخاص، وعلى موقع المزوّد عند تفعيل صندوق البريد.
  مع من متصل الآن، ورسالة «عاجلة»، و«رسائل جاهزة» بنقرة، وتنبيه صوتي، وأرقام غير المقروء في القائمة.
- **المختبرات:** لكل حاسوب مفتاحه (X25519) و«بطاقة تعارف» (نص وQR) وبصمة تُقارن بالهاتف. الرسالة لمختبر تُشفَّر له وحده، وتصل:
  **باتصال مباشر** (WebRTC، «رمز دعوة» و«رمز رد» بلا أي وسيط؛ STUN اختياري للإنترنت ولا يرى الرسائل)، أو **بملف** مشفّر يُنقل
  بأي وسيلة، أو **بصندوق البريد المشفّر** لدى المزوّد (موقوف افتراضياً؛ يحمل الرسائل ولا يقرؤها، وتُحذف عند استلامها).
- **المحادثة العامة** بين كل المختبرات (على موقع المزوّد): باسم مستعار (يُعلَّم بأنه مستعار) أو باسم المختبر من رمزه (لا يمكن انتحاله)،
  بلا أي معلومة أخرى. للمالك الإشراف: يرى المختبر وراء كل اسم، ويحذف رسالة (تختفي عند الجميع)، ويوقف مختبراً عن الكتابة.
- الرسائل على الحاسوب فقط (لا تدخل في المزامنة) وتُحذف بعد المدة المختارة. ما يُرسل للمختبرات حسب رغبة المختبر.
- إعداداتها: اسم الحاسوب واسم البطاقة، رمز المحادثة، الاسم في المحادثة العامة، صندوق البريد وSTUN والمفتاح، مدة الحفظ والتنبيه
  والرسائل الجاهزة، النسخ الاحتياطي (المفتاح والمختبرات والرسائل)، ورمز الدخول (PIN) والمظهر.
- فتح صندوق البريد يتطلب إثبات امتلاك المفتاح (لا يكفي معرفته من البطاقة)، وللمرسل الواحد حدّ في صندوق كل مختبر.

**رموز الأطباء ونافذة الأطباء** (`src/lib/doctors`؛ «محطة المزامنة ← رموز الأطباء» و`/doctor`):
- المختبر ينشئ لكل طبيب رمزاً (12 حرفاً ورقماً، يظهر مرة واحدة، مع زر نسخ وإرسال بواتساب) ويختار المدة: آخر يوم أو أسبوع أو شهر أو سنة.
- يرى الطبيب زيارات المراجعين المكتوب اسمه «الطبيب المحيل» فيها (تُقرأ «د. أحمد» و«الدكتور احمد» و«Dr Ahmed» اسماً واحداً)،
  ويربط المختبر أي طريقة أخرى لكتابة اسمه بالرمز من «أسماء الأطباء في الزيارات». الزيارة بلا أي نتيجة لا تظهر.
- لكل رمز: إخفاء هاتف المريض (مفعّل افتراضياً)، المكتملة النتائج فقط، والقيم الطبيعية وH / L؛ و«رمز جديد» (يتوقف القديم فوراً)
  و«إيقاف الرمز» (تُحذف نسخته من الخادم).
- لا يُحفظ الرمز ولا يصل إلى الخادم: يُشتق منه مفتاح واسم (PBKDF2)، ويرفع حاسوب المختبر الذي أنشأ الرموز (كل بضع دقائق وهو مفتوح
  في محطة المختبر أو المزامنة) نسخة مشفّرة لكل طبيب (XChaCha20-Poly1305) تحل محل السابقة. الرموز على ذلك الحاسوب فقط ولا تدخل في المزامنة.
  على موقع المزوّد يُرفع برمز المختبر، ولا يستطيع مختبر آخر استبدال النسخة أو حذفها، ومحاولات الرموز الخاطئة الكثيرة من عنوان واحد تُبطَّأ.
- «نافذة الأطباء» (`/doctor`) مستقلة مثل `/license`: لا بطاقة لها في صفحة الترحيب ولا رابط إليها من أي صفحة، والمختبر يرسل عنوانها مع الرمز.
  لا يظهر فيها شيء قبل إدخال «رمز التفعيل» (رمز الطبيب لدى المختبر)، وإذا أوقف المختبر الرمز أو استبدله تعود شاشة التفعيل.
  بعد التفعيل: نتائج كل المختبرات التي فعّل رموزها، مرتبة بالأحدث مع علامة «جديد»
  وبحث وتصفية (اليوم / أسبوع / شهر)، وفتح الزيارة كتقرير باسم المختبر وتذييله مع طباعة؛ وإعداداتها رمز الدخول والمظهر و«خروج» يمسح كل شيء.
  تعمل بلا إنترنت بآخر نتائج وصلت.
- للمالك في `/license ← الإعدادات العامة` مفتاح «نافذة الأطباء» (مفعّل افتراضياً) يوقف الرفع والعرض لكل المختبرات.

**إيقاف المزامنة** («محطة المزامنة ← الإعدادات ← الحماية»): زر لكل حاسوب يوقف إرسال واستقبال أي بيانات — المزامنة التلقائية
وملف المزامنة معاً — حتى تشغيلها؛ التعديلات أثناء الإيقاف تُرسل بعد التشغيل.

**عن التطبيق** (`/about`): محطة شرح بقائمة جانبية مثل باقي المحطات — نظرة عامة، البدء السريع، صفحة لكل محطة
(المختبر، التقرير المطبوع، المخزن والمشتريات، التدريب، الجودة، الكادر، التواصل، المزامنة، لوحة الإدارة)، البيانات والأمان، النصائح،
الأسئلة الشائعة، والتفعيل والدعم. النص ثابت في `src/lib/about/content.ts` والصور رسوم مبسّطة (`src/components/about/Art.tsx`)
تعمل بالمظهرين وبلا إنترنت. إعداداتها المظهر وحجم الخط فقط، ولا يُعدَّل فيها شيء من المحتوى. لا تحتاج رمز مختبر.

**الدليل** (`/training/guide`، أول ما في محطة التدريب): دليل كامل من الصفر في 13 فصلاً (`src/lib/training/guide.ts`):
المختبر ورحلة العينة والوحدات، السلامة، الأجهزة والأدوات، التيوبات وترتيب السحب، سحب العينة، الفصل وجودة العينة،
أقسام الفحوصات وأهميتها والحزم الشائعة، طرق الفحص، ضبط الجودة (وستغارد)، قراءة النتيجة والقيم الحرجة وأنماط التشخيص،
كتابة التقرير، قاموس المصطلحات، وفهرس الفحوصات. أدوات المختبر وتيوباته وأقسامه وفهرسه تُملأ من بيانات المحطة نفسها.
يُتصفّح بفهرس جانبي وبحث، ويُطبع كتاباً (غلاف ومحتويات وكل فصل في صفحة جديدة) أو فصلاً واحداً.
- **قابل للتعديل كله** (زر «تعديل الدليل»، ويحترم وضع القراءة فقط): عنوان كل فصل ومقدمته وأقسامه، وفقرات وقوائم وخطوات
  وملاحظات وجداول (سطر لكل صف و«|» بين الخانات) وصور من مكتبة الصور، وقوائم من بيانات المحطة، ووصف أهمية كل قسم من الفحوصات؛
  مع تحريك وحذف وإضافة فصول. يُحفظ تلقائياً في `training.guide.v1` (ومع النسخة الاحتياطية للمحطة)، و«النص الأصلي» يعيد فصلاً
  أو الدليل كله. المكونات: `GuideView.tsx` (العرض والطباعة) و`GuideEditor.tsx` (التعديل).
- **الطباعة بشعار المختبر ومعلوماته:** الغلاف بالشعار والاسم والعنوان الفرعي والعنوان والهاتف، ورأس المختبر أعلى المحتويات وكل فصل،
  وسطر التذييل. تُكتب في «الإعدادات ← المطبوعات» أو تُنسخ بزر «نسخ من محطة المختبر» (الاسم والمعلومات والشعار).
وطباعة البروسيجرات كلها في كتاب واحد صارت «طباعة البروسيجرات» (`/training/manual`).

**مكتبة التدريب:** تأتي محطة التدريب بكل فحوصات محطة المختبر (92 فحصاً + صورة الدم الكاملة، `src/lib/training/library*.ts`) بأقسامها،
ولكل فحص: الغرض ومبدأ الطريقة، والعينة والحجم والتيوب وتحضير المريض والحفظ، وخطوات العمل (مع تحذيرات)، وملاحظات الخبرة،
والقيم الطبيعية (من قائمة محطة المختبر نفسها)، وأسباب الارتفاع والانخفاض، والربط بالفحوصات الأخرى، وحل المشاكل؛ مع التيوبات
والأجهزة اللازمة (محلل الأملاح، محلل المناعة، ELISA، الكاسيت، اللاتكس، أوساط الزرع…). المحطات القديمة تُضاف إليها الفحوصات
الناقصة مرة واحدة دون تغيير ما عدّلته، و«الإعدادات ← الجهاز والبيانات ← إضافة فحوصات المكتبة الناقصة» يعيد ما حُذف.

**سجل المتدربين** (`/training/trainees`): لكل متدرب أو موظف سجل الكفاءة وشهادة الإتمام (عند الاستقلالية)، ومعهما:
**شهادة انتهاء التدريب** (تاريخ الانتهاء، البرنامج، الساعات، التقدير، المشرف، ورقمها يُحفظ) مطبوعة بعرض A4،
و**كتاب توصية** لمتدرب أو موظف سابق (المسمى، الفترة، الجهة، نص مقترح يُعدَّل، اسم الموصي ومنصبه) مطبوع على ترويسة المحطة.

**ربط المحطات** (كلها عدا التدريب، على الحاسوب نفسه):
- المخزن في «المخزن والمشتريات»: يُحسم منه عند إدخال فحص مرتبط (محطة المختبر) وعند كل إدخال سيطرة لمادة كنترول مرتبطة (الجودة)، ويُضاف إليه ما يُشترى.
- الجودة: أسماء الفحوصات من محطة المختبر، و«المنفّذ» من الكادر، وشركة صيانة الجهاز من موردي المشتريات (مع هاتفه).

**محطة المزامنة** (`/sync`، بلون بنفسجي): نظرة عامة بلوحة حالة (متزامن / يحتاج مزامنة)، وهذا الحاسوب وسجلاته لكل محطة، وآخر العمليات؛
«المزامنة بملف» بإرسال واستقبال جنباً إلى جنب مع سحب الملف وإفلاته ومعاينة ما فيه ونتيجة بالأرقام؛ وسجل مجمّع بالأيام مع تصفية.
 «ملف المزامنة» يُصدَّر من حاسوب ويُدخل في آخر (يُضاف الناقص، ويؤخذ الأحدث، ويُحذف ما حُذف لاحقاً)،
أو «المزامنة التلقائية» كل 30 ثانية عبر مكان المختبر على الخادم (`/api/company-sync`، بالترخيص الموقّع للجهاز فقط)،
أو عبر «خادم الشبكة المحلية» (`LAN_HUB_KEY`) على حاسوب المختبر بلا إنترنت. من إعداداتها تُختار المحطات المشتركة.

**المخزن والمشتريات:** بيانات المخزن مشتركة مع محطة المختبر والجودة على الجهاز نفسه:
- الإدخال بسيط: كل إضافة أو تعديل في نافذة صغيرة (اسم وكمية ثم «حفظ»)، والقوائم نظيفة مع بحث وتصفية بنقرة.
- «المشتريات والمخزن والأسعار» (`/store`، و`/store/inventory` تفتحها على المخزن) صفحة واحدة بتصميم محطة المورّد، و«الموردون» تحتها في القائمة:
  بطاقات الأرقام (الأصناف، النفاد، قرب الانتهاء، قيمة المخزن، المصروف، غير المدفوع)، ثم «إدخال مخزني»: «شراء من مورّد» أو «رصيد افتتاحي / تسوية» (يدخل المخزن فقط)،
  وفي الشراء «مدفوعة»، ثم جدول البنود — Enter في خانة المجموع يضيف سطراً.
  **اسم المورّد** و**رقم فاتورته** مخفيان، ويظهران بخيار «اسم المورّد ورقم الفاتورة» في «الإعدادات ← خيارات إضافية» (ودائماً مع «ديون الموردين»)؛
  و**التاريخ** تاريخ اليوم تلقائياً، وخانته تظهر بخيار «تاريخ الشراء». كل سطر: النوع **صنف** أو **كت** (قائمتان منفصلتان)،
  **الجهاز** (اختياري، يُحفظ على الصنف ويأتي معه في الشراء التالي) و**المادة** في عمودين (يظهر رصيدها إن كانت في المخزن، أو «صنف جديد»)، **العدد** (مثلاً 1 كت ← «يُضاف إلى المخزن: كاشف × 30»)،
  **الاكسباير** و**اللوت** (اختياريان؛ يُكتبان على الصنف في المخزن، ويبقى أقرب اكسباير)، **سعر الواحد** و**المجموع**
  (أيهما كُتب حُسب الآخر، وتغيير العدد يُبقي سعر الواحد؛ وللكت من صنف واحد يظهر سعر الوحدة التي فيه، مثلاً 60,000 ÷ 30 = 2,000).
  **«طلبية لم تصل بعد»**: لا تدخل المخزن ولا تُحسب مصروفاً ولا ديناً حتى «استلام». ومع «الباركود» في الإعدادات: مسح بالقارئ
  أو **بالكاميرا**، وباركود **GS1** على العلبة يملأ اللوت والاكسباير ويُحفظ باركوداً للصنف.
  تحتها تبويبان: «المخزن والأسعار» (جدول: الجهاز، المادة، الرصيد، الإكسباير، الكلفة، القيمة، الحد الأدنى، الحالة، «استلام كمية»، إضافة وصرف) و«سجل المشتريات» (جدول الأحدث أولاً، بحث بالمورّد أو الفاتورة أو الصنف، تصفية «الكل / غير مدفوعة / مدفوعة /
  بانتظار الاستلام»، تحديد وحذف جماعي، «تم الدفع» والنقر على «مدفوعة» يرجعها، والنقر على البنود يعرض تفاصيلها).
- «المخزن» (`/store/inventory`): كل صنف بكميته بخط كبير و«نفد / ناقص»، وتصفية «نفد أو ناقص» و«قرب الانتهاء»،
  و«إضافة» و«صرف» في نافذة الكمية (1 افتراضياً، Enter للحفظ)، وزر سجل حركته وتعديله.
- «الأصناف» (`/store/items`): زرّا «صنف جديد» و«كت جديد»، وعلامتا تبويب:
  - «الأصناف والكتات» في أقسام: **الكواشف** (تُحسم مع النتائج، وحدة لكل تحليل)، **المستلزمات** (أنابيب، سرنجات، علب،
    قفازات، قطن، كحول… يصرفها الفاحص بنفسه، مع «مستلزم جديد» و«إضافة المستلزمات الشائعة»)، **مواد السيطرة**، و**الكتات**.
    تحت كل صنف الكتات التي يأتي فيها (مثلاً «يأتي في: كت السكر × 4»)؛
  - «التحاليل وموادها»: كل تحليل من «إدارة الفحوصات» في محطة المختبر وكاشفه (زر «مادة» يضيف «كاشف …» مرتبطاً به،
    أو مادة لكل تحليل بلا مادة دفعة واحدة) والمستلزمات التي يُستعمل معها.
- الكت علبة تُشترى وتحتوي أصنافاً بكميات (مثلاً 4 × كاشف + 1 × محلول معايرة)؛ في نافذة الكت يُختار الصنف أو يُكتب اسم
  صنف جديد فيُضاف إلى الأصناف عند الحفظ. يُكتب اسم الكت في «المشتريات» فتُضاف محتوياته × عدد الكتات إلى المخزن.
- «الجرد» (`/store/count`) بتصميم محطة المورّد: لكل جهاز موادّه، وما صُرف في الفترة (منذ آخر جرد افتراضياً، أو كل المدة، أو من — إلى)
  والمتبقي في السجل، ثم العدد الفعلي (اختياري) والفرق؛ «أعمدة إضافية»: الإكسباير، الوارد، قيمة المتبقي، الكلفة. «حفظ الجرد» يصحّح المعدود فقط
  مع تاريخه وملاحظته، والفروقات في «سجل الحركة»؛ و«سجل الجرد» بمحضر لكل جرد، و«طباعة ورقة الجرد» للعدّ بالقلم.
- «اقتراح الشراء» (`/store/reorder`): المواد عند حدّها الأدنى أو التي لا تكفي صرف N يوماً (حسب معدّل آخر 90 يوماً)، مجمّعة حسب آخر مورّد؛
  الكمية والمورّد يُعدَّلان، و«طلب شراء» للطباعة، و«إرسال إلى المشتريات» يسجّلها طلبية «بانتظار الاستلام».
- «سجل الحركة» (`/store/moves`): كل تغيّر في الكمية (شراء، حذف شراء، نتائج، سيطرة، إضافة/صرف يدوي، جرد، تعديل) مع الكمية بعده
  (`station.stockMoves.v1`، آخر 3000 حركة).
- خيارات إضافية موقوفة في البداية (إعدادات المخزن والمشتريات ← خيارات إضافية):
  - **ديون الموردين:** «المدفوع الآن» ودفعات لاحقة لكل عملية («تم الدفع» يسجّل المتبقي دفعة)، والمتبقي لكل مورّد، وكشف حساب المورّد للطباعة؛
  - **الأسعار وقيمة المخزن:** سعر الوحدة من آخر شراء (أو يُكتب)، وقيمة المخزن، وكلفة المواد لكل فحص؛
  - **الباركود:** لكل صنف وكت، ومسحه بقارئ الباركود في المشتريات والمخزن والجرد.
- حسم المواد (خيار واحد في إعدادات محطة المختبر وإعدادات المخزن والمشتريات ← المخزن): **تلقائي** عند حفظ النتيجة
  وعند كل إدخال سيطرة، أو **يدوي** — زر «صرف المواد من المخزن» تحت النتائج في شاشة الإدخال، أو «المخزن ← بانتظار الصرف»
  (الزيارات وإدخالات السيطرة) مع «صرف» و«تجاهل». لا تُحسم مواد الزيارة أو إدخال السيطرة مرتين أبداً
  (السجلان `station.stockUsed.v1` و`station.stockUsedQc.v1`).
- تُحسم وحدة من الكاشف تلقائياً عند إدخال فحص مرتبط به في محطة المختبر؛
- كل بند مشترى يُضاف إلى المخزن (الموجود تُزاد كميته والجديد يُضاف صنفاً)، وحذف عملية الشراء يطرح الكميات.
- الكاشف يُربط بفحوصات محطة المختبر ويُحسم وحدةً لكل فحص. أما **المستلزمات** (الأنبوب، سرنجة سحب الدم، العلب، القفازات…)
  فلا تُحسم مع النتائج لأن أنبوباً أو سرنجة واحدة قد تكفي عدة تحاليل: يصرفها الفاحص من «المخزن» (تصفية «المستلزمات» ثم «صرف»)،
  وتظهر مع تحاليلها للعرض فقط (EDTA لأمراض الدم، الجل للكيمياء، علب الإدرار والخروج…).
- «عند نفاد المادة» (خيار واحد يظهر في إعدادات محطة المختبر وإعدادات المخزن والمشتريات، موقوف في البداية):
  تحذير «غير متوفر في المخزن» تحت الفحص وتنبيه عند الحفظ (تُحفظ النتيجة)، والسماح بالرصيد السالب (مثلاً -1) بدل التوقف عند 0.
- حقول الأرقام تقبل الكتابة بلوحة المفاتيح العربية وتحوّلها إلى 1 2 3، والمبالغ تظهر بالشكل 25,000.

**فحص الإدرار العام (G.U.E):** الخلايا (القيح وكريات الدم الحمراء) والفحوص الكيميائية (الألبومين، السكر، الكيتون، الصفراء)
بالإشارات Nil, +, ++, +++, ++++, More than (++++) — بدون أرقام وبدون Trace.

**التقرير المطبوع في محطة المختبر** (الإعدادات):
- باركود رقم العينة بجانب معلومات المريض يمكن إخفاؤه (يبقى الرقم مطبوعاً).
- الفحوص ذات النتيجة الموجبة/السالبة تُطبع بلا مدى مرجعي ولا Flag.
- «تمييز» في استمارات الإدرار والخروج والسائل المنوي والزرع: لكل حقل (وسطر الزرع وكل مضاد) علامة تلوّنه على التقرير.
- الطباعة على عدة صفحات: كل صفحة فيها الترويسة وباركود رقم العينة ومعلومات المريض ورأس الجدول في أعلاها، والتوقيع ورمز QR
  وسطر التذييل في أسفلها. هوامش صفحة المتصفح صفر (فلا يطبع تاريخه وعنوانه ورابط الصفحة ورقمها)، وهوامش التقرير نفسه
  (A4: 10/12 ملم، A5: 7/9 ملم) تبعد التذييل عن حافة الورقة. وتُطبع الصفحة دائماً من أعلاها (زر الطباعة تحت النتائج كان يطبع
  صفحة منزلقة للأسفل فيختفي التوقيع ورمز QR والتذييل).
- «ملء الصفحة» (قسم مستقل في الإعدادات تحت «التقرير المطبوع»، موقوف في البداية): يكبر خط الجدول وتتسع أسطره كلما قلّت
  الفحوص؛ ويُشغَّل أو يُوقف أيضاً بزر «ملء الصفحة» بين زر الطباعة وزر واتساب تحت إدخال النتائج. وفي القسم نفسه طرق إضافية
  (كلها موقوفة، وتعمل حين يكون ملء الصفحة مشغّلاً — `src/lib/station/fillPage.ts`): **ملء ذكي** يقيس الفراغ الفعلي في الورقة
  ويكبّر الجدول حتى يملأه (ويبقى في صفحة واحدة)، **التكبير حسب حجم الورق** (أكثر على A4 وأقل على A5)، **مربع ملاحظات**
  بأسطر للكتابة باليد فوق التوقيع، **تكبير الترويسة ومعلومات المريض**، **عرض البطاقة** لفحص أو فحصين (النتيجة بخط كبير)،
  **النتيجة السابقة عند وجود مساحة**، و**درجة التكبير** (خفيف / متوسط / كامل).
- زر «واتساب» بجانب زر الطباعة: يُفتح واتساب مباشرة على محادثة المريض (رقمه بالصيغة الدولية 964…)، أو واتساب لاختيار المريض إن لم يكن له رقم، ويُحفظ التقرير ملف PDF لإرفاقه في المحادثة.
- ألوان المختبر: ألوان جاهزة أو خاصة، وشدة الألوان، مع معاينة فورية.
- شكل جدول النتائج (الخط، الأسطر، الكثافة…).
- خيارات إضافية موقوفة في البداية:
  - الطباعة على ورق مطبوع مسبقاً؛
  - مكان الشعار والعلامة المائية؛
  - خط التقرير (Cairo / Tajawal / Noto Naskh / Amiri، مضمّنة للعمل بلا إنترنت).
- التوقيع والختم، ورمز QR بمعلومات المختبر.

### 2. لوحة الإدارة الكاملة (مدفوعة) — `/`

- المرضى والطلبات والنتائج والفواتير والمخزون والمشتريات والكادر والمواعيد والجودة.
- **نافذة ساحب الدم** (`/collect`، للمدير والاستقبال ودور «ساحب الدم»):
  - المراجع (بحث بالاسم أو الهاتف، أو جديد)، والفحوص بأسعارها، والخصم والمدفوع وطريقة الدفع؛
  - تُحفظ العيّنة «بانتظار المختبر» مع فاتورتها ودفعتها (فتظهر في الصندوق والديون)، ثم الوصل وملصقات الأنابيب؛
  - عيّنات اليوم بحالتها، واستلام الباقي، وتسليم النتيجة بعد اعتمادها.
  - دور «ساحب الدم» يرى نافذته فقط (يدخل إليها مباشرة، ويطبع الوصل والملصقات).
- **نافذة المختبر** (`/lab`، للمدير والفني) — تعمل مثل محطة المختبر، بلا أسعار:
  - قائمة: بانتظار المختبر / قيد العمل / معتمدة اليوم، مع مدة الانتظار و«متأخرة» بعد المدة المحددة، ومسح رقم العيّنة؛
  - «عيّنة جديدة» مباشرة من المختبر (بلا أسعار)، وإضافة فحص لعيّنة الساحب؛
  - إدخال النتائج: الترميز H/L حسب الجنس والعمر، الاقتراحات النوعية، النتيجة السابقة والفرق، «تمييز»، الفحوص المشتقة،
    واستمارات الإدرار والخروج والسائل المنوي والزرع؛
  - القيم الحرجة (لكل فحص في كتالوج الفحوصات): تظهر فوراً، ولا تُعتمد النتائج قبل تسجيل من أُبلغ بها؛
  - الاعتماد، واعتماد ثانٍ اختياري من شخص آخر، وإعادة الفتح للمدير، والتسليم؛
  - الطباعة بتقرير محطة المختبر وخياراته (الورق، ملء الصفحة، التاريخ والوقت، الورق المطبوع مسبقاً، الخط، الشعار، الباركود، QR،
    ملصقات الأنابيب، واتساب PDF)، و«إشعار المراجع» بواتساب مع رابط التحقق.
  - الإعدادات للمدير من زر الإعدادات في النافذة (تُحفظ في `lab_settings`).
  - الجداول: `supabase/migrations/0030_desk_workflow.sql` (تُضاف لقاعدة الموقع تلقائياً عند أول استعمال).
- **مراقبة الجودة** (`/quality`): المحاليل الضابطة بمستوياتها، السيطرة اليومية بقواعد Westgard (1-2s، 1-3s، 2-2s، R-4s، 4-1s، 10x)،
  مخطط Levey-Jennings الشهري مع الإحصاء والطباعة، سجل درجات الحرارة صباحاً ومساءً (والإجراء عند الخروج عن الحدود)،
  والأجهزة: الصيانة الدورية (يومي … سنوي)، المعايرة وموعدها، والأعطال حتى إصلاحها. والتشغيلات السريعة القديمة باقية.
- **الكادر** (`/staff`): الراتب، «الحضور والانصراف» بضغطة (وبداية الدوام للتأخير)، «الإجازات والسُّلف»،
  و«الرواتب» الشهرية: الراتب − (الغياب والإجازة بدون راتب × الراتب ÷ 30) − سُلف الشهر، مع الطباعة.
- **المخزون** (`/inventory`): «الجرد» الكامل بفروقاته وسجله، «حركة المخزون» لكل مادة وسبب، و«العبوات» (Kit فيها عدد من الوحدات)،
  و«المادة المستهلكة» لكل فحص في كتالوج الفحوصات تُخصم تلقائياً عند الطلب.
- **رموز الأطباء** (`/referrers/codes`، للمدير): رمز لكل طبيب محيل يحفظه المختبر، فيختم الخادم نتائج مراجعيه المعتمدة
  ويرفعها لـ«نافذة الأطباء» عند كل اعتماد وتسليم (بلا حاجة لحاسوب يبقى مفتوحاً).
- **استيراد من المحطات** (`/settings/import`، للمدير): ملف النسخة الاحتياطية لمحطة المختبر — فحوصاتها (الناقص يُضاف للكتالوج)،
  ومراجعوها وأطباؤها وزياراتها بنتائجها، كل زيارة مرة واحدة، بلا أسعار وبلا خصم من المخزون.
- القائمة الجانبية تعرض ما ينتظر (عيّنات المختبر، النتائج الجاهزة للتسليم، المواد الناقصة، أعطال الأجهزة)، ولوحة التحكم تبدأ بـ«يومي» حسب الدور.
- الجداول: `supabase/migrations/0031_quality_staff_stock.sql`.
- **الحسابات** (للمدير والاستقبال):
  - «الصندوق اليومي» (`/cashbox`): الداخل لليوم (دفعات الفواتير، والطلبات المعلَّمة «مدفوع» عند الاستقبال بلا فاتورة) حسب طريقة الدفع،
    والمصروف (يُضاف من الصفحة نفسها)، والصافي، والمتوقع نقداً في الصندوق؛ «إغلاق اليوم» بالمعدود والفرق (`cash_closings`) مع إعادة الفتح؛
    وملخص الشهر: الداخل والمصروفات (حسب التصنيف) والمشتريات والصافي، وجدول الأيام بحالة إغلاقها؛ مع الطباعة.
  - «الديون» (`/debts`): الفواتير غير المدفوعة أو المدفوعة جزئياً مجمّعة لكل مريض، الباقي ومنذ كم يوم، وتذكير بواتساب برقمه.
  - «حصص الأطباء» (`/referrers/commissions`): نسبة لكل طبيب محيل (`referrers.commission_pct`)، وإحالاته في الشهر وما فُوتر عليها
    وحصته، وكشف شهري لكل طبيب للطباعة بخانتي التوقيع.
- واتساب ومساعد ذكي اختياري.
- يدخلها المختبر بحساب مستخدم (`/login`).
- لكل مختبر هويته في الإعدادات:
  - اسمه وشعاره؛
  - ألوان تقريره؛
  - التوقيع والختم؛
  - التقرير بالعربية أو الإنجليزية، مع زر للتبديل عند كل طباعة.
- **بيانات كل مختبر منفصلة:**
  - إما في قاعدة بيانات خاصة به (يربطها المالك أو المختبر نفسه)؛
  - أو في قسم مستقل له داخل قاعدة الموقع (مخطط `lab_<id>`).
  - شاشة «لوحة الإدارة تحتاج قاعدة بيانات خاصة» (إلزام الرموز المدفوعة بقاعدة خاصة) **معطّلة بطلب المالك** (`src/lib/license/flags.ts`)،
    فيعمل كل مختبر في قسمه المستقل حتى تُربط قاعدته.
- التحقق من صحة التقرير عبر رمز QR يفتح `/verify/<token>`.

### 3. مدير الرموز (للمالك) — `/license`

- **لوحة الرموز:** أرقام في الأعلى (الفعّالة، التي اتصلت اليوم، التي تنتهي قريباً، غير المدفوع)، وبحث سريع، وعرض 40 رمزاً ثم «عرض المزيد».
- **قسم «المحطات»:** كل محطة وعدد الرموز الفعّالة التي تستعملها ومن اتصل اليوم، والمحطات الافتراضية، ومحطة المزامنة (مع كل رمز)
  و«عن التطبيق» (للجميع) — وتظهران أيضاً في محطات كل رمز وفي رسالة التفعيل.
- **رموز المختبرات:** رمز لكل مختبر يحدد المحطات المفعّلة ومدة الاشتراك، ويرتبط بجهاز
  واحد أو بعدة أجهزة.
- **متابعة الرموز:** سجل الأحداث، والدفعات، ورسائل للمحطات، ونسخة احتياطية للرموز.
- **قسم «رموز الدخول (PIN)»:** لكل عميل: إخفاء خاصية رمز الدخول أو إظهارها (تعود الرموز كما كانت)، وتعيين رمز كل محطة
  أو تغييره أو إزالته، و**عدة رموز للمحطة نفسها** (من هنا فقط)، مع حالة «وصل الجهاز / بانتظار اتصال الجهاز». تُحفظ بصمة الرمز فقط.
  (العنوان القديم `/licenses` يحوّل إلى `/license`.)
- **قسم «محطة التواصل»:** صندوق البريد المشفّر (موقوف افتراضياً)، و«المحادثة العامة» (مفعّلة) مع رسائلها والمختبر وراء كل اسم،
  وحذف رسالة، وإيقاف مختبر عن الكتابة أو إعادته.
- **دخول المالك:** بكلمة مرور، مع تحقق بخطوتين اختياري (تطبيق المصادقة).
- **قسم «قواعد البيانات»:** ربط قاعدة كل مختبر بواجهة لكل مزوّد (Neon / Supabase /
  Railway / PostgreSQL آخر) مع تعليماته، وفحص الاتصال، وإعادة كلمة مرور المدير.
- **قسم «الإعدادات العامة»:**
  - مدة الرمز الافتراضية، والمحطات الافتراضية، ومدة التجربة.
  - ميزات موقوفة في البداية: عدة أجهزة للرمز، التسجيل الذاتي (`/signup`)، سجل الأخطاء.
  - ميزة سرية: تصدير بيانات مختبر إلى Excel.
  - «نافذة الأطباء» (مفعّلة): رموز الأطباء في محطة المزامنة ونافذتهم `/doctor`.

```bash
npm install

```

- يعمل التطبيق على PGlite (Postgres مدمج)، ويطبّق الهجرات والبيانات التجريبية تلقائياً.

## متغيرات البيئة

انظر [`.env.example`](.env.example) للتفاصيل. أهمها:

| المتغير | الغرض |
|---|---|
| `DATABASE_URL` | Postgres المستضاف للموقع. بدونه: PGlite (مؤقت على Vercel). |
| `AUTH_SECRET` | سر توقيع الجلسات وتشفير روابط قواعد المختبرات ومفتاح الرموز. **إلزامي في الإنتاج.** |
| `LICENSE_ADMIN_PASSWORD` | كلمة مرور المالك لـ `/license`، ووجوده يشغّل منظومة الرموز. |
| `LICENSE_URL` | قاعدة مستقلة للرموز (مستحسن). بدونه تُستخدم `DATABASE_URL`. |
| `LICENSE_2FA_OFF` | `1` لإيقاف التحقق بخطوتين مؤقتاً عند فقدان الهاتف. |
| `STATION_ACTIVATION_CONTACT` | سطر التواصل على شاشة التفعيل (يُعدَّل أيضاً من `/license`). |
| `NEXT_PUBLIC_BASE_URL` | عنوان الموقع لروابط QR (يُستنتج تلقائياً إن لم يُضبط). |
| `NEXT_PUBLIC_STATION_SYNC` | `1` لإظهار مزامنة المحطات مع قاعدة المختبر (موقوفة افتراضياً). |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | المساعد الذكي في لوحة الإدارة (اختياري). |
| `WHATSAPP_CLOUD_TOKEN` / `WHATSAPP_PHONE_ID` | واتساب Cloud API الرسمي (اختياري؛ بدونه روابط wa.me). |
| `LAB_POOL_IDLE_MIN` / `LAB_POOLS_MAX` | إغلاق اتصالات قواعد المختبرات الخاملة وحدّها الأقصى. |
| `PGSSL` / `PGPOOL_MAX` / `PGLITE_DATA_DIR` | ضبط الاتصال بـ Postgres ومكان بيانات PGlite. |

> لا تُكتب قيم الأسرار في المستودع أو في المحادثات؛ تُضبط في إعدادات Vercel فقط.

## النشر على Vercel

1. أنشئ قاعدة Postgres للموقع (Neon عبر Vercel → Storage، أو Supabase) واضبط `DATABASE_URL`.
2. (مستحسن) قاعدة مستقلة للرموز: Vercel → Storage → Neon باسم `LICENSE` ← `LICENSE_URL`.
3. اضبط `AUTH_SECRET` (`openssl rand -base64 48`) و`LICENSE_ADMIN_PASSWORD`.
4. الإنتاج يُبنى من فرع `main`؛ كل تغيير يمر بطلب دمج تُشغَّل عليه الاختبارات.

الهجرات تحت `supabase/migrations` تُطبَّق تلقائياً على قاعدة الموقع وعلى قاعدة كل مختبر
(جداول لوحة الإدارة فقط؛ جداول الرموز تبقى في قاعدة الرموز).

## الفحوصات والاختبارات

```bash
npx tsc --noEmit     # الأنواع
```

اختبارات المتصفح (Playwright) تعمل على خادم مشغَّل:

```bash
# الرموز موقوفة: المحطات والاستمارات والصفحات ولوحة الإدارة
PORT=3456 npm start &
E2E_BASE=http://localhost:3456 npm run test:e2e

# الرموز مفعّلة: مدير الرموز وقواعد المختبرات (يحتاج Postgres في E2E_PG_URL)
PORT=3457 LICENSE_ADMIN_PASSWORD=… AUTH_SECRET=… LAB_DB_ALLOW_PRIVATE=1 npm start &
E2E_BASE=http://localhost:3457 E2E_PG_URL=postgresql://… npm run test:e2e:codes
```

- GitHub Actions (`.github/workflows/tests.yml`) تشغّل كل ذلك على كل دفع وطلب دمج، مع خدمة
  Postgres 16.
- ويعمل تدقيق أمني للحزم (`security.yml`) أسبوعياً وعند كل تغيير في الحزم.
